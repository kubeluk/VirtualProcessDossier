# Competency Questions

These questions describe information that can be retrieved from the VPD data model when the corresponding records and links are populated. Here, part X refers to the laminate associated with a workflow run.

## Part and material traceability

1. How was part X manufactured?
2. What is part X made of?
3. Which workflow runs are associated with part X, and which workflow model did each run execute?
4. What are the recorded length, width, and thickness of part X, including their units?
5. Which layup was the laminate derived from, and what is the ordered stack of tapes in that layup?
6. What fiber orientation does each tape have within the layup?
7. What polymer, fiber type, and fiber mass fraction are recorded for each tape?
8. Where are the laminate's needle points, in which units, and relative to which reference point?

Example data: [laminate.ttl](../laminate.ttl), [run-view-after-demo.ttl](../run-view-after-demo.ttl).

## Workflow structure and execution

9. Which atomic and composite activities make up a workflow model, and how are they nested?
10. In what order are the activities in each sequential group specified to occur?
11. Which activities are grouped to run in parallel, such as heating and surface temperature observation?
12. Which activity instances belong to a workflow run, and which model activity does each instance execute?
13. What is the recorded state of a workflow run and each of its activity instances?
14. When did a workflow run and its activities start and end, and what durations follow from those timestamps?
15. Which activities have a recorded completed execution in a given run, and which have no such record?

Example data: [workflow.ttl](../workflow.ttl), [run-view-after-ui.ttl](../run-view-after-ui.ttl), [run-view-after-demo.ttl](../run-view-after-demo.ttl).

## Equipment and system context

16. Which system is specified to implement an activity, and which system was associated with its recorded execution?
17. Which subsystems and sensors belong to a given system, including through nested subsystem relationships?
18. Which gripper contains a particular angle, force, or extension sensor, and which frame contains that gripper?

Example data: [system.ttl](../system.ttl), [workflow.ttl](../workflow.ttl), [run-view-after-demo.ttl](../run-view-after-demo.ttl).

## Initialization and process parameters

19. Which initialization plans were assigned to a workflow run and to its gripping, heating, and pressing activity instances?
20. What gripper positions were specified by the initialization plan, in which units, and relative to which reference?
21. What setpoint was specified for each gripper during gripping, heating, and pressing?
22. What heating threshold temperature and stable holding time were specified for a run?
23. What target temperatures were specified for each infrared field and heating device?
24. What press force, mold temperatures, mold cooling time, and remaining path were specified for a run?
25. What is the ordered press closing profile, including the closing speed and remaining distance at each step?
26. Which parameters does a system accept, and what units, datatypes, defaults, and cardinality constraints are declared for them?

Example data: [plan.ttl](../plan.ttl), [parameter.ttl](../parameter.ttl), [system.ttl](../system.ttl).

## Observations and measurement context

27. Which observations were recorded during a given workflow run, and which workflow activities do they instantiate?
28. Which sensor made an observation, what entity was observed, and which property of that entity was measured?
29. Which observations measured the surface temperature or surface geometry of part X?
30. Which observations measured the angle, force, or extension of a particular gripper during a run?
31. During what recorded time interval did an observation take place?
32. What initialization settings were assigned to the manufacturing activities in the run containing a given observation?

Example data: [run-view-after-demo.ttl](../run-view-after-demo.ttl), [properties.ttl](../properties.ttl), [plan.ttl](../plan.ttl).

## Dataset discovery and provenance

33. Which datasets are registered in the VPD catalog, and what titles and descriptions are recorded for them?
34. Where can a dataset be downloaded, and what media type and temporal resolution are recorded for each distribution?
35. Which observation generated a dataset, and which sensor, observed entity, and observed property provide its measurement context?
36. Which workflow run and workflow model provide the process context for a given dataset?
37. Which datasets were generated by observations in a given workflow run or by runs of a given workflow model?
38. Which datasets describe part X directly, and which describe equipment observed during the same manufacturing run?

Example data: [catalog.ttl](../catalog.ttl), [run-view-after-demo.ttl](../run-view-after-demo.ttl). Dataset-to-observation links are also illustrated by the [dataset insertion template](../queries/updates/sensor-activities/demonstrator/template-insert-dataset.rq).

## Scope of the examples

The two run-view files are snapshots of the same run before and after execution. The completed snapshot uses synthetic timestamps that respect sequential ordering and contain each child interval within its parent interval. They illustrate execution structure and are not measured production times. Load only one snapshot into a graph at a time.

The catalog defines its two generating observations as standalone examples, separate from the illustrative workflow run. Their sensors, observed entities, properties, and run assignments are not supplied. Questions that traverse from these datasets to sensors, parts, or runs require actual execution context, as illustrated by the insertion template; the catalog examples do not establish a connection to the sample run.

The examples describe measurement context and link to external data files. Questions about actual temperature curves, measured force values, geometric deviations, or whether a part meets quality tolerances additionally require the measurement contents and, where applicable, acceptance criteria. Initialization parameters alone describe the specified settings.
